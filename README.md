# DN1Sup SketchUp Profiles

Расширение SketchUp 2026 для работы с профилями: у каждого профиля — **свой
набор расширений и свои настройки интерфейса**. Переключение профиля из
диалога закрывает SketchUp, внешний хелпер меняет набор и перезапускает
SketchUp автоматически.

## Как это работает (схема v2)

Установленные расширения SketchUp 2026 живут в общем реальном каталоге
`%APPDATA%\SketchUp\SketchUp 2026\SketchUp\Plugins` — и SketchUp 2026
**не регистрирует расширения**, если этот каталог (или каталог версии)
перекрыт NTFS-junction (проверено на 26.2). Поэтому изоляция сделана на
уровне отдельных расширений:

```
Plugins (реальный, общий)
  ├── <ext_id>.rb          ← регистраторы: реальные копии из хранилища профиля
  └── <ext_id>/            ← junction на profiles\<активный>\Plugins\<ext_id>

%LOCALAPPDATA%\dn1sup_sketchup_profiles\
  profiles\<id>\Plugins\   ← образ Plugins профиля: .rb-копии + папки расширений
  profiles\<id>\Prefs\     ← SharedPreferences.json + PrivatePreferences.json
                             (настройки интерфейса; свапаются при переключении)
  profiles.json / state.json / backups\ / logs\ / su_profiles_helper.ps1
```

SketchUp видит обычный реальный каталог Plugins с реальными `.rb` —
регистрация и автозагрузка работают как обычно. Каждой папке расширения
соответствует junction на хранилище активного профиля: разные профили —
разные наборы и версии кода расширений. Настройки интерфейса (раскладка
панелей, флаги расширений) изолированы свапом двух JSON-файлов настроек.

**Переключение** (внешний хелпер, SketchUp закрыт): сохранить свежие `.rb`
и настройки уходящего профиля → очистить реальный Plugins (файлы удалить,
junction-ы снять — оригиналы в хранилище не трогаются) → наполнить из
хранилища целевого профиля (`.rb` копией, папки junction-ами) → применить
его настройки → перезапустить SketchUp.

Изоляция полная для расширений и настроек интерфейса. Общими остаются:
материалы/стили/шаблоны/компоненты, Ruby-гемы, лицензия и вход Trimble,
предустановки `C:\ProgramData\SketchUp`, настройки LayOut.

## Возможности

- **Инициализация** (одноразовый мастер): текущий набор становится профилем
  «Основной»; сразу можно создать «Разработку» (только `dn1sup_*` + dev) и
  «Черчение» (рабочий набор сторонних, без `dn1sup_*`).
- **Переключение профиля** — SketchUp закрывается, хелпер меняет набор и
  перезапускает SketchUp (несохранённые модели предложит сохранить).
- **Создание профилей**: клон другого профиля с фильтром расширений
  (только `dn1sup_*` / всё, кроме `dn1sup_*`); настройки наследуются.
  Отдельные варианты: **пустой** (только менеджер, интерфейс наследуется) и
  **чистый** (только менеджер и Save Settings, настройки интерфейса
  генерируются с нуля — дефолтные панели и тулбары).
- **Установка .rbz в выбранный профиль** (распаковка в его хранилище; для
  активного — плюс зеркало в реальный Plugins) и удаление расширений.
- **Снимки профилей** (zip: Plugins + Prefs, 10 последних на профиль) и
  восстановление (кроме активного профиля).
- Менеджер **сам копируется в каждый профиль** — переключаться можно из
  любого; кнопка «Синхр. менеджера» обновляет его во всех профилях.

GUI — HtmlDialog: Vue 3 + Tailwind CSS (единый стек DN1Sup). Меню:
`Extensions → DN1Sup → Профили SketchUp`, есть кнопка на панели инструментов.

## Ограничения

- **Активен один профиль одновременно.** Второй запущенный экземпляр
  SketchUp блокирует переключение: хелпер отменит операцию и напишет
  причину в журнал (`logs\helper-*.log`).
- Установка расширений в активный профиль подхватывается после перезапуска
  SketchUp (Plugins сканируется при старте).
- Одиночные `.rb`-скрипты без папки (например, `fillet.rb`) — общие для всех
  профилей: изолируются только расширения «`.rb` + папка».
- Восстановление снимка недоступно для активного профиля.
- Новая версия SketchUp (например, 2027) — другой путь Plugins: инициализацию
  придётся выполнить заново для нового года.

## Внешний хелпер

`dn1sup_sketchup_profiles/helper/su_profiles_helper.ps1` — единственная
часть, работающая вне SketchUp. Запускается скрыто (WScript.Shell) перед
закрытием SketchUp: дожидается выхода процесса (по PID), выполняет job,
пишет прогресс по фазам в `pending_job.result.json`, журнал — в `logs\`,
перезапускает `SketchUp.exe`. Файл обязан сохраняться в UTF-8 **с BOM**
(PowerShell 5.1 иначе читает его как ANSI). Если автоперезапуск не произошёл
— смотрите последний `logs\helper-*.log`.

## Разработка

- Тесты: `ruby test/smoke_test.rb` (песочница, CI-совместимо),
  `ruby test/helper_sandbox_test.rb` (Windows, живой PowerShell + junction),
  `ext_test id=dn1sup_sketchup_profiles_dev` — в живом SketchUp.
- Frontend: `cd frontend && npm run dev` (браузер, mock-режим) /
  `npm run build` (single-file в `dn1sup_sketchup_profiles/html/`).
- Сборка .rbz: `ruby tools/pack.rb` → `dist/`.
- Dev-цикл и публикация — по правилам `U:\dn1code\sketchup_ext\AGENTS.md` /
  `PUBLISHING.md` (мастера).
