# Changelog

## [0.6.6] — 2026-10-17

### DN1Sup SketchUp Profiles (v0.6.6)
- **Обновление — только из GitHub.** Из манифеста и вызовов проверки удалён
  устаревший `dev_dir`. Копия общего апдейтера обновлена до v5 (единая

## [0.6.5] — 2026-10-16

### DN1Sup SketchUp Profiles (v0.6.5)

  Extension Store (цветной квадрат, знак с «воздухом»); работает в светлой
  и тёмной теме. Источник — `dn1sup_extensions` (`tools/make_icons.rb`).
## [0.6.4] — 2026-10-16

### DN1Sup SketchUp Profiles (v0.6.4)

  Store: два профиля (indigo), прозрачный фон, вырезы — настоящая прозрачность

## [0.6.0] — 2026-10-16

- Удаление профиля удаляет его снимки: `delete_profile` сносит zip-архивы
  профиля (`<id>-YYYYMMDD-HHMMSS.zip`) и вычищает сиротские снимки без
  профиля; подтверждение показывает число снимков, экран «Снимки»
  обновляется после удаления.
- Авточистка сирот: `get_backups`/`delete_backup` перед отдачей списка
  удаляют снимки, чей профиль отсутствует в `profiles.json`.

## [0.4.10] — 2026-10-16

- Защита от размножения SketchUp: хелпер перезапускает приложение только
  как рестарт — при `wait_pid > 0` и отсутствии других процессов SketchUp

- Тесты обезврежены: `run_helper_sync!` в живых тестах принудительно ставит

- Удалены остатки `_dev`-двойников: переходный маркер `.sketchup_dev.json`
  убран из `dev_source?` (обе копии `dn1sup_updater.rb`), `_dev`-фикстуры
  убраны из `smoke_test.rb` / `helper_sandbox_test.rb`.

## [0.4.0] — 2026-10-14

- Удалены режимы создания «только dn1sup_*» и «всё, кроме dn1sup_*/dn1c_*»
  вместе со связанными фильтрами: новый профиль — клон источника, пустой
  (только менеджер) или чистый (менеджер + Save Settings). `create_profile`
  принимает `mode: clone/empty/clean` вместо `include/exclude/clean`.
- Инициализация больше не предлагает профили «Разработка»/«Черчение»:
  создаётся только «Основной», остальные — кнопкой «Новый профиль».
- Поддержка SketchUp 2024 и новее: год версии определяется по живому
  окружению в приоритете над сохранённым state, инициализация требует
  2024+ (`MIN_SUPPORTED_YEAR`). Хранилище изолировано по версии
  (`SU<год>` под общим корнем): профили и настройки разных SketchUp не
  смешиваются; старый плоский стор 0.3.x один раз переезжает в папку
  текущей версии автоматически (для перенесённых каталогов остаётся
  junction-мостик на новое место — живые подключения Plugins продолжают
  работать до следующего переключения профиля).

- Удалён функционал dev/prod (второй id `<id>_dev`): удалены `DEV_BUILD`,
  поле `dev_build` в состоянии, бейдж DEV в шапке и классификация
  расширений `kind: 'dev'` (остатки старых двойников показываются как
  обычные `dn1sup_*` и удаляются штатно). Разработка — рабочая копия под
  тем же id; self-update рабочей копии отключён по пути загрузки
  (`Dn1sup::Updater.dev_source?`); файлы `.sketchup_dev.json` удалены.

## [0.2.0] — 2026-10-12

- **Чистый профиль**: новый вариант в форме «Новый профиль» — копируются
  только менеджер профилей и Save Settings, настройки интерфейса
  (SharedPreferences/PrivatePreferences) не наследуются: при первом запуске
  профиля SketchUp генерирует дефолтные панели и тулбары.
- Исправлен режим «пустой профиль»: раньше он копировал все расширения
  источника (пустые фильтры ядро трактовало как «ничего не исключать»);
  теперь «пустой» = только менеджер профилей, интерфейс при этом
  наследуется от источника как раньше.
- Состав чистого профиля — константа `CLEAN_KEEP` в ядре (`profile_core.rb`),
  `create_profile` принимает флаг `clean`; неудачное создание чистого
  профиля откатывается как обычное.

## [0.1.1] — 2026-10-12

- Фронтенд: транслитерация id профиля из названия (кириллица → латиница),
  валидация и суффикс при коллизии — профиль не создавался, если UI отправлял
  кириллический id.
- Долгие операции (создание/удаление профиля, установка/удаление расширения,
  снимки) — блокирующий оверлей прогресса в диалоге с фазами из ядра
  (get_progress-опрос); перезапуск диалога посреди операции восстанавливает
  оверлей.
- Подтверждения (удаление профиля/расширения, восстановление из снимка)
  перенесены внутрь диалога: нативный UI.messagebox из колбэка HtmlDialog
  в SketchUp 2026 молча игнорируется.
- create_profile при неудаче откатывает свежесозданное хранилище и мету —
  на диске не остаётся папок-сирот.
- Футер диалога больше не показывает ложное предупреждение о junction
  (схема v2 Pref-junction не использует).
- Файловые операции (создание/удаление профиля, .rbz, снимки) выполняются
  синхронно на главном потоке под блокирующим оверлеем: в SketchUp 2026
  фоновые Ruby-потоки замерзают, пока главный поток молчит в event-loop
  (Thread+timer-схема defer_async для них ненадёжна — операции зависали
  без результата и тоста). Сетевые проверки апдейтера остались асинхронными.
- Команды get_progress больше не засоряют INFO-лог (log_debug); у задач
  появились отметки «задача начата/завершена» для диагностики.

## [0.1.0] — 2026-10-12

Первый выпуск.

- Профили SketchUp 2026: у каждого профиля свой набор расширений и свои
  настройки интерфейса. Схема изоляции v2: реальный каталог Plugins с
  реальными .rb-регистраторами + NTFS-junction на папки отдельных расширений
  (SketchUp 2026 не регистрирует расширения, если Plugins или каталог версии
  перекрыты junction целиком — проверено на 26.2), плюс свап файлов
  SharedPreferences/PrivatePreferences при переключении.
- Мастер первичной инициализации: текущий набор становится профилем
  «Основной», сразу можно создать «Разработку» (только dn1sup_*) и
  «Черчение» (рабочий набор сторонних).
- Переключение профиля из диалога: SketchUp закрывается, внешний
  PowerShell-хелпер меняет набор расширений и настройки и перезапускает
  SketchUp; мьютекс от параллельного запуска, строгая проверка «второй
  экземпляр SketchUp», журнал и result-файл по фазам.
- Установка .rbz в выбранный профиль (распаковка в хранилище профиля,
  для активного — зеркало в реальный Plugins) и удаление расширений;
  менеджер автоматически копируется в каждый профиль.
- Снимки профилей (zip: Plugins + Prefs) и восстановление из них.
- GUI: HtmlDialog, Vue 3 + Tailwind CSS (единый семейный стек), меню
  Extensions → DN1Sup и кнопка на панели инструментов.
